# V4.3 升级逻辑复核

日期：2026年10月25日。对象：`1464356758/xiaishuo-ZUOZONG`空母版。

原基线提交：`e6bf8057a0f4b2d9ef89ba67aa4814c8f2458aff`。本次只改系统，不复制小说、不初始化作品、不登记投稿或平台发布。

## 结论

本次将两轮研究中能适配单GPT的部分，落实到文件工具、发布前检查、初始化包及执行指令。**流程与版本逻辑已通过本地验证，新增检查没有替代原有冻结与事实边界。**

写作质量仍由实际正文判断。工具能拦截漏步骤、过期来源、伪造引文和未处理问题，不能自动证明情节有吸引力，也不能保证90万字文学质量或签约。

## 一、为什么这样改

|原风险|实际改动|设计理由|
|---|---|---|
|写手直接接触大量状态与制作记录|登记自然语言任务书；独立writer资料，只加必要边界、场景安排及上章正文|减少控制语言进入叙述的机会，仍保留作者端完整核对|
|八千至一万字容易扩写手续|写前场景作用与汉字预算，预算合计核对章长|先判断内容能否支撑长章；预算不替代正文实测、不机械切场景|
|章纲说推进，但正文没有对应事件|actual_scenes＋plan_comparison，要求正文引文|把计划与已发生的结果分开，避免只改表格完成任务|
|审稿拿大纲补正文缺口|reader资料排除canon、roadmap与原始章后摘要|让“正文有没有讲清”与“是否符合设定”形成两种检查视角|
|同一GPT换身份被误称盲读|必须声明近似模式，确有独立输入才可用隔离模式|避免虚构独立读者验证；不额外引入多智能体或作者转发|
|只比最近三章，长期反复用同一办法|全书摘要与推进索引检索，报告绑定索引并列旧章与本章证据|覆盖更早候选桥段；未命中须补别名与方法检索，不能宣称自动语义去重|
|配角被动、对白像汇报、重大事件没余波|同一报告检查对立方、对白与余波，允许说明不适用|重点核查人物因果，不强迫每章出现反派、对话或高潮|
|作者真相混入读者前情|读者回顾区分observed、claim、uncertain，并绑定本章原文|回顾是派生视图，不增加一套客观事实源|
|制作语言混入成稿|扫描少量明确制作句、字段与行内标签，逐项处理|提醒不直接判文学；普通编号不一律删除，真实故事语境可说明|
|规则堆叠让成本失控|核心检查合并到一份release；专项技法按缺陷调用|不增加评分员、无限返修或全量技法加载|

第一轮的卖点兑现、全书反重复、专项修文与负例验证，以及第二轮的信息揭示、人物弧线、带立场材料、同终点备选路径和机制借鉴，分别落入任务书、release字段及《专项技法》。没有把十二项全部变成每章新增文件。

## 二、状态链是否闭合

|检查点|规则与复核结论|
|---|---|
|空母版→开书|仍需作者明确开书、选择平台、完成研究及选题；本次升级未创建state或书籍身份|
|来源→任务书|任务书绑定book_id、chapter、revision、canon、roadmap；不跨书，不把未来计划存成事实|
|任务书→候选|任务书准备不修改候选任务与修订次数；实际完整正文仍需candidate登记|
|候选→审查|报告额外绑定任务书哈希；正文、记录、任务、修订次数、路线任一变化均重新检查|
|审查→修订|证据成立的问题才修；必须修与待核未完成不得冻结，表达偏好可以保留|
|修订→重审|同一任务最多三轮；重做任务书或新聊天不能清零。正文变化后新引文、新记录、新报告对应同一稿|
|审查→冻结|原八项、承诺期限、旧错处置、近期路线及到期全文回看都保留；新叙事项集中追加|
|冻结→续写|冻结正文与事实记录不改；任务书、读者回顾和检索都是派生资料，不回写历史事实|
|冻结→发布|仍以真实回执或作者明确确认为依据；没有把adopt、导出或GitHub可见当成平台已发|
|中断→恢复|任务书不可变保存并登记；快照同时携带新增运行模块和规程，恢复仍保持冻结边界|

任务书登记不增加正式revision，与候选登记的准备性质相同；它的变化另以哈希进入release绑定，因此不会出现“revision没变，所以旧报告还能用”的漏洞。

旧书没有新检查开关时仍走原流程。底层init不带配置是兼容入口，新书用bootstrap读取新版system_config。升级工具版本不能追认既有章节通过新检查，更不能通过手改state解冻。

## 三、重点失败场景与验证

|场景|实际验证或明确边界|
|---|---|
|没有任务书就准备新书发布前报告|拒绝，候选不会被采用|
|任务书属于另一部书或旧路线|拒绝，必须依据本书当前来源重新准备|
|登记了新任务书，复用旧通过报告|拒绝；额外测试确认候选与修订次数没有清零|
|引用“只在计划里发生”的事件|伪造引文会被拒绝；引文真实但解释不成立仍须GPT判断|
|未处理的读者理解问题|must_fix／verify处于open会被阻断；可选建议不会强制整章重写|
|没有对白的章节|允许具体说明不适用，不强塞对白|
|第六章需要找第一章同类桥段|历史检索实际返回最近三章以外的来源，仍要求回读原文比较|
|人物说法进入更早读者回顾|claim标签保留，不自动转换为世界真相|
|读者资料偷偷带入原始章后摘要或未来设定|用特定标记做负例，writer/reader资料不含作者秘密与原始摘要中的未来信息|
|“她知道第十五章完成的是……”和行内审稿标签|扫描命中，不能删掉提醒假装完成；须改当前稿后重新检查|
|普通P11、R03编号，或老道士、知道等正常词|不按一般编号和单字判制作污染|
|中文紧贴英文控制字段|复核发现英文词边界会漏检，改为ASCII标识符边界，并新增中文相邻测试|
|资料超预算|不输出静默截断稿；reader可按章分批，author按不可变来源分批读取|
|context输出路径指向冻结正文|命令拒绝，原冻结文件保持不变|
|初始化包换仓库|测试启动两本新书，身份不同，均默认启用冻结与叙事检查，0章、等待选平台|
|快照恢复|新增模块及规程存在；恢复后冻结与叙事开关保持|

旧版存储回归用例原先关闭serial_mode，但复制了新书默认叙事开关，形成不合法的测试配置。已把这些合成旧工程明确设为两个开关均关闭，保留旧迁移测试目的；没有放松新书生产校验。

测试文本均为临时合成数据。重复文本能通过流程压力测试，恰好说明文件校验不是文学判断：不能把“119项通过”换算成签约概率或收入。

## 五、还需实际稿件验证的部分

1. 干净任务书是否漏提了关键硬约束，需要作者端回读原文核查；程序无法证明自然语言提取完整。
2. 实际场景是否有分量、对白是否成立、人物是否有情感，不能由非空字段和引文存在性证明。
3. 同一上下文仍会受大纲影响；隔离声明也不是工具检测到了真实独立读者。
4. 摘要、读者回顾和关键词召回都会有误差；长篇关键历史仍要读原文，到期全文回看没有取消。
5. 模型可能写出泛泛结论或不当解释引文。执行时必须拒绝这种审稿，不能用脚本替真实稿件自动填写通过。

这些是明确保留的能力边界，不用更多自评分或固定数字掩盖。后续应在少量未冻结正文上观察误报、修订效果和实际读者、编辑反馈，再决定是否继续增加规则。

## 六、交付与继续使用

核心实现：`tools/narrative_quality.py`、`tools/novel_state.py`、`tools/serial_release.py`。

执行入口：`AGENTS.md`、`启动新书.txt`、`每日一章指令.txt`及新增两份规程。初始化生成器与快照均包含新模块。

本母版保持空书状态。继续优化可直接接管最终仓库；正式开书时使用新版初始化包建立各自独立的新仓库，再选择平台和题材。
