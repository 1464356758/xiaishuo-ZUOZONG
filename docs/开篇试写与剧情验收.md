# 开篇试写与剧情验收

V4.4 的新书先验证读者能在正文里得到什么，再投入长篇生产。GitHub 继续保存实际稿件、设定和采用记录。由同一个 GPT 入口执行，作者沿用选题、开始写和下一章指令。

## 选题与试写

1. 按目标平台找同题材、同阅读体验的近期作品。记录样本的实际可读范围，并说明它何时给出第一项看得见的成果。只有简介或榜单时，开篇写法留待核实。
2. 每个候选列出前三章的因果链。第一章主角出手并造成有分量的结果，第二章让成果产生代价或反击，第三章回答首个短期问题并打开下一条线。题材可以决定成果是赢一局、失去筹码、改变一段关系或证实一条关键线索。
3. 作者选题并授权写作后，先试同一前提的两种原创开场，各约300—800汉字，保存在 drafts 下。让两个开场切入不同事件，例如当场被拒与反制已开始。只看样稿，记录谁在做什么、何处想停、哪一问值得往下看。选择一个能支撑完整首章的版本。两版都不成立就先重排开篇。
4. 用胜出方向完成本轮目标章。前三章以约2500—3500汉字为写作预算，默认上限4500，剧情完整即可收束。第4章起按本书连载配置执行。默认长线仍规划100章、约90万汉字。确定全书结构时把开篇实际篇幅算进预算。作者要求不同章长时，在新书初始化前配置。

## 写前约定

在原有 brief 里填写 story_plan。首章还在 opening_trial 登记两份短开场原文、各自留下的问题和薄弱处，以及最终选用的编号和理由。程序检查两稿有实际正文并且各不超过1000汉字，writer 资料只带选中的样稿。用故事语言说明人物眼前要解决的问题、会作的选择、将实际发生的结果及由此出现的压力。再排场景和预算。全书规划用于约束时间、动机和边界。作者事实、账目、权限细节只提取本场必需的部分。

选题时可以先写“她要取得第一笔收入”。任务书要进一步明确这笔收入来自什么交付、谁验收、女主作出什么决定、失败损失什么。采用时回查钱是否到了她手里。换成悬疑，可以是主角主动验证了谁能进入密室，让原有嫌疑转向，下一场因此必须重新决定信任谁。

## 先读正文再验收

先读正文的前800汉字和前3000汉字，再读完整候选。首章用正文证据确认读者已看见冲突、类型承诺和第一次有效结果。读完后从正文反推人物的处境与因果，最后对照原任务书。已见过大纲的审读仍填写 same_context_approximation。确实只把读者资料交给独立输入环境时才能填写 isolated_input。

在同一份 release 报告里填写 narrative_review.story_review。五项分别给出裁定、结论和原文。

| 检查 | 正文要回答的问题 |
|---|---|
| 主线 | 读者能说清主角此刻最想解决什么吗？中途是否被低价值事务挤走？ |
| 行动 | 哪个选择由主角作出？对手、处境或关系因此怎样回应？ |
| 最弱段落 | 引用最容易让读者跳过的一段。删掉后若只损失重复说明，就删或合并。若损失情绪转折、关系变化或关键线索，说明保留的作用。 |
| 兑现 | 分别引用行动和结果，说明前后变化及它兑现的具体承诺。等审批、领钥匙、签字、写计划可以构成过程。要看它们是否已经改变核心处境。 |
| 续读 | 结果使下一步变得怎样不同？用选择、压力或线索支撑读者的新问题。 |

影响阅读的结构问题填 revise，在当前候选返修中移动成果、合并场景或改变行动路径。出现两次重复交涉时，先合并，再把省下的篇幅用于行动和后果。避免让旁白复述读者已从人物行为看出的道理。情绪段落可以有呼吸，保留有独立作用的细节。沿用同章最多三轮的修订上限。

第三章采用前一起读前三章原文，填写 opening_arc。写出开篇第一个问题已获得的答案、已经发生的结果、读者接下来关心的问题，并逐章附当前正文引文。未完成的长线可以继续，首轮短期问题须已有结果。

脚本核验字段、引用、版本、开篇位置和阻断结论。是否好看由实际审读判断。自评分、文本检测和程序通过均没有平台评估效力。

## 反例

- 经商开篇写了接铺、点货、议价、验样，结尾还在等订单。若承诺是靠本领翻身，应让一次独到判断引出已验收的小单或另一项能改变谈判地位的实际结果。
- 求生开篇破封、认责、等搬运，受困者还在原处。若承诺是靠能力救人，安排一次已有成效的干预，再用资源减少或连带伤害构成下一难题。
- 悬疑开篇不断遇到可疑人，每章用新谜遮住旧谜。让主人公证实一条有限线索，承担由此产生的行动成本，留更深的问题。
