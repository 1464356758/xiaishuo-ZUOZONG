# 每日目标与恢复协议

本工具不调用模型，沿用 V4.3 任务书、叙事审读、三轮修订、采用冻结和发布回执规则。不以新增文件或聊天中的完成声明代替真实成果。

## 首次进入每日任务

在当前小说仓库的最新默认分支工作，先确认远端提交头并回读当前状态，再运行：

```bash
python3 tools/daily_update.py --project . begin
```

- started：记录本次 run_id、目标章和前文基线。先将 book/daily/active.json 原子写回远端并回读，确认没有并发版本冲突，再开始正文。
- already_completed：本日已经完成，不再写下一章。
- verify_in_progress：存在正在执行或中断的目标，先核实原执行是否停止；不能仅因超时自动抢占。
- recovered_completion：目标已经采用但回执尚未落盘，按工具读取到的实际采用时间恢复回执并同步。不能将昨日采用日期改成今天。本次先保存和回读，再根据作者指令处理后续工作。
- 报错：如实处理。未选平台、未定题、尚无 canon/roadmap 或旧书没有冻结机制时，不绕过流程自动开写。

## 写作和完成

沿用原工作流准备资料、任务书、候选正文、写后记录、审读和 release-check，再 adopt。adopt 现在为新采用章记录 adopted_at；旧章不追补或改写采用日期。

```bash
python3 tools/daily_update.py --project . finish --run-id 实际执行编号
python3 tools/online_state.py --project . build-index
python3 tools/online_state.py --project . validate-index
```

finish 核对目标章、前文版本、冻结正文、章后记录及已使用的审查报告。完成回执写入 book/daily/实际采用的北京时间日期.json，active.json 标记完成。

将正文、状态、执行记录、回执和索引作为同一批更改写回。保留基础树，以预期分支头进行非强制更新。冲突后读取远端；旧 run_id 已被恢复执行替换时，旧执行不能继续写回。提交后回读正文、回执与状态，成功才能说已经完成。

工具无法替你证明远端同步、实际阅读行为或文学质量。只在临时工作区完成，仍然不算已写入 GitHub。

## 中断和恢复

```bash
python3 tools/daily_update.py --project . block --run-id 实际执行编号 --reason '真实中断原因'
```

把中断状态同步回仓库。不得记录凭证、登录状态或其他秘密。常见 GitHub 凭证格式会被隐去，但不要把任意秘密交给 reason。

仅当原执行确实停止，作者或当前执行已经核实时，才运行：

```bash
python3 tools/daily_update.py --project . begin --resume-stopped
```

恢复保持原目标、开始日期、前文基线和核心任务的修订计数，更换本次 run_id 并保留上次尝试。先同步恢复记录再继续同一章，不直接开下一章。

由于 GPT 任务在不同临时工作区运行，程序本地锁不是跨机器锁。必须执行“记录远端原子保存并回读后才能写作”的协议。没有联网写入或并发冲突时就停止，不能以本地锁存在为理由继续。

普通手动创作不自动建立计划。平台实际发布仍使用原 publish 命令，必须有真实回执或作者明确确认；每日完成记录不是发布回执。
