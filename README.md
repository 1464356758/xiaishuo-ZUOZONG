正式母版：<https://github.com/1464356758/xiaishuo-ZUOZONG>。

一个GPT入口，GitHub保存真实状态。由V4.2空母版升级，新增干净写作任务书、场景预算、限信息审读、正文实际推进核对和全书相似桥段检索；继续保留采用即冻结、三轮返修、承诺期限、前向处错和真实发布回执。

## 当前状态

- 这是空系统母版，没有小说、书籍身份、平台选择或投稿记录。
- `online/index.json`是未初始化空索引，0章、0汉字。
- 母版继续保持空白，软件维护不自动初始化小说或投稿。
- `初始化系统包.zip`用于各个独立新仓库，不含本母版仓库绑定或旧作品资料。

## 每章流程

恢复真实状态 → 阅读相关事实与历史 → 准备并登记干净任务书、场景预算 → 检索全书同类桥段 → 生成writer资料并写完整一章 → 从正文提取实际变化 → 限信息审读及人物因果检查 → 必要局部修订 → 到期全文回看 → release-check → adopt冻结 → GitHub提交回读 → 作者发布并单独登记回执。

同一任务最多三轮修订。新任务书不清零候选或次数。来源、正文或任务书变化后旧报告失效。无对白、无对手出场时说明不适用，不硬塞场景。

每天续写时，全部旧采用章及其事实记录只读，不以平台发布登记为条件；只能修订当前尚未采用的目标章。冻结状态异常时停止，重开完稿流程也不解冻旧章。本轮核验与兼容范围见《docs/旧章只读核验.md》。

工作台1.4.1及初始化包新增固定日更执行器：GPT写作，GitHub Actions运行Python、记录控制者、处理失败并同步索引；工具命令完成与章节完成分开。见《docs/定时执行器.md》。旧running归属不明时保留待核实，不自动抢占；单次故障不自动关闭每日计划。

## 个人管理端与代发端

- `web/dist/index.html`：个人端，直接阅读正文、选择小说生成代发码，新增和修改自动保存GitHub，随时查询今天更新。
- `web/dist/reader.html`：代发端，输入编码定位码，核验正式正文后阅读、复制、导出，并记住本机复制进度。
- `web/dist/legacy.html`：保留原平台研究、选题和阅读功能。
- `tools/daily_update.py`：每日目标、执行编号、中断恢复和真实采用日期回执；不调用模型。
- 工作台1.4.2：个人端新增“新书指令”，输入独立仓库即可生成附带初始化包使用的完整部署与开书指令；支持选填平台和题材偏好，保护已有作品，沿用选题等待及旧章冻结规则。见`docs/网页部署与首次使用.md`。
- 工作台1.4.0：书名与仓库关键词搜索；日更、阅读、代发选书均可筛选；两端按章号和标题找章节；今日更新结果支持筛选，搜索不改变查询勾选。见`docs/工作台搜索.md`。
- 工作台1.3.0：手机列表直接显示常用操作；个人端记住阅读章号，整本导出防重复和切书干扰；代发进度按小说与分支隔离，改稿提示复核。日更指令复用每书唯一任务，可登记实际反馈对话，并单独核验本日正式完成证据。见`docs/工作台1.3最终复查.md`。
- 工作台1.2：勾选小说后随时查询今天更新，按最新章节文件的提交日期判断，分开显示未更新和读取失败；最近7天记录可随清单同步。见`docs/今日更新查询.md`。直接阅读、代发码和自动保存继续保留。
- 网络修复1.0.1：Sites同站GitHub通道、raw失败时固定提交的Contents备用读取；Netlify包包含可选网络函数，部署说明见`docs/网页部署与首次使用.md`。
- `tools/query_today.mjs`：与网页今日查询共用按章节文件提交日期判断的规则；`tools/check_updates.mjs`保留为独立严格采用证据核验，不能混用两种口径。
- `个人管理端部署包.zip`、`代发端部署包.zip`、`管理仓库初始化包.zip`：可独立部署或初始化的空包，无小说和凭证。

首次使用见《docs/网页部署与首次使用.md》，数据协议见《docs/管理端与代发端.md》，定时写作见《docs/每日自动更新.md》。网页不会自动创建或取消ChatGPT计划，须在对应聊天确认真正建立的定时任务。

## 使用与接管

```text
接管小说系统最终母版：https://github.com/1464356758/xiaishuo-ZUOZONG
先读取AGENTS.md、README.md、project_config.json及docs/写作与叙事检查.md。
当前是V4.3空系统，尚未创建小说。按我本次任务执行并真实写回、回读；不要复制旧小说，不因接管自动开书。
```

需要开新书时，把初始化包解压到一个新的GitHub仓库，将新链接和《启动新书.txt》发送给GPT。默认100章、每章8000—10000汉字、约90万字。先选平台、核查规则与榜单，再由作者选题。多本书使用不同仓库、独立身份、事实账和投稿记录；共用方法，不共用剧情。

新包bootstrap默认开启叙事检查。旧工程仍按现有state.config执行，不自动追认旧章补审或解冻；底层不带配置的init是迁移兼容入口。主版本表示工具版本，实际检查配置另查status。

```bash
node --test web/tests/*.test.mjs
python3 tools/make_init_package.py
python3 tools/build_web_package.py
```

测试使用临时目录与明确合成文本。程序可核查文件、版本、引文和覆盖，不证明模型真的读完、文学判断正确、作品会签约或产生收入。同一GPT对话不能真正忘掉大纲，读者审读必须如实标近似。

原复制来源及证据保留在`MIGRATION_MANIFEST.json`和`docs/迁移核验.md`，它们描述V4.2历史基线，不代表本版仍未升级。
