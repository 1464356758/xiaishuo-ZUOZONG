# 网页部署与首次使用

个人端是 index.html，代发端是 reader.html。1.0.1部署包包含网页与可选的GitHub网络函数，没有小说正文、登录凭证或模型 API Key。程序需通过 HTTP/HTTPS 托管，不建议直接双击本地 HTML（浏览器可能禁止模块或跨域请求）。

## 部署

1. 将个人管理端部署包解压，把包内文件作为站点根目录部署。
2. 合作人可以使用同一站点的 reader.html，也可以单独部署代发端部署包。单独代发包的根页也是阅读端。
3. 分开部署时，在个人端“代发工具”填写真实的 reader.html 网址，然后保存到本机。
4. 代码修改需要部署；小说、清单、报告更新无需重新部署。中国大陆网络的实际访问情况应在自己的设备和网络下验证。

### GitHub读取通道

当前Sites在线版使用同站的`/api/github`服务读取GitHub；手机只需连接网站，不再要求手机同时直连api.github.com和raw.githubusercontent.com。正文仍从公开仓库实时读取，不复制到服务器数据库。匿名API额度不足时使用公开Git版本发现，仍取得真实提交号，不拿索引时间冒充版本。raw下载失败时，程序用GitHub Contents接口读取同一提交的同一文件；两个来源都失败才显示实际错误。

Netlify包附带`netlify/functions/github.mjs`和路由配置。使用Git连接部署，或支持函数的Netlify CLI部署，让函数与网页一起发布。仅把文件拖进静态托管区不会部署函数；这种部署仍需浏览器可直连GitHub。纯静态托管发现没有函数时会使用直连，不假装已经启用网站通道。

网站函数不保存小说、清单或凭证。小说正文与Git版本发现不带凭证；个人端保存时，用户临时填入的GitHub凭证通过本站转发给GitHub，不落库、不写日志、不放URL；显式授权的管理API读取可使用同一凭证。代发端独立包的函数为只读。写入中断时不自动换线路重复发送，先重新读取远端。

Sites使用`tools/build_site_worker.py --out /临时目录/worker/index.js`把实际网页和通道打成单文件Worker，沿用已有站点身份与访问权限。该构建不创建GPT任务，也不调用计费模型API。

## 第一次连接

1. 准备独立公开管理仓库，上传管理仓库初始化包，确保至少有一次提交。
2. 个人端“连接与设置”填写管理仓库链接和分支。只读可以不填凭证。
3. 保存清单需要临时填写仅授权此管理仓库的 GitHub Contents 写入凭证。浏览器刷新即清除；启用网站通道时经本站服务器临时转发，不保存到服务器、小说或管理文件，不进入本机备份。
4. 添加每部小说的公开仓库。软件自动识别正式章节并建立接入基线；聊天链接仅保存在本机。
5. 勾选检查范围，点击列表底部“保存到 GitHub”。只有写入后回读核对成功，才显示已经保存。

不支持仅凭公开仓库链接写入。权限、分支保护、授权范围或访问限流可能导致保存失败；失败时保留本地修改。不要把凭证发给合作人。

## 定时任务

在各书的“更多”中查看本书定时指令，到对应 GPT 聊天实际创建任务，确认编号、启用状态和下次执行时间。总任务指令位于首页底部。

网页保存计划时间不等于 ChatGPT 已创建计划。取消勾选只影响检查；停写须到 ChatGPT 暂停计划，正在执行的任务另行停止。

十本写作加一次检查的任务数量、实际额度、后台工具权限需要账号实测。软件不自动购买额外额度、不自动切换到付费 API。

## 日常使用

- 夜间任务写入 reports/latest.json；个人端读取并显示报告日期和清单版本。
- “实时核验仓库”直接检查当前本地清单，不依赖 GPT 日报。结果只在当前页面展示，不冒充已经写入远端日报。
- 未生成今日报告、旧清单报告、读取失败都明确标记，不显示成今天一切正常。
- 漏更后先打开原 GPT，查看并复制补更指令，恢复同一目标章。任务仍在运行或状态未知时不要并发补写。
- 阅读、复制、导出之前核对正文 SHA-256。代发端不显示仓库首页链接，但公开仓库无法通过编码变成私有。
- 收益和人工时间是本机手工记录，不代表自动获取平台数据。定期导出本机备份，备份含聊天链接和收益记录，应自行保管。换设备时可在设置中导入，核对管理仓库版本后再决定是否保存清单；导入不会自动写远端，也不携带凭证。
- 原平台研究与选题功能保留在 legacy.html。

网页及网络函数不会自动创建 GitHub 仓库、自动操纵 ChatGPT 聊天、自动取消 ChatGPT 计划或自动到小说平台投稿。
