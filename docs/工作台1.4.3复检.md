# 工作台1.4.3复检与修复

核查日期：2026-10-30，北京时间。基线源提交：1385a72699b08578b7344cd9ca7a165ac9fd1c87。范围为个人端、代发端、初始化包和它们共用的读取及交接逻辑。

## 修复内容

1. 新书页面原先直接跳转GitHub下载ZIP；改为同站`downloads/novel-init.zip`。Sites Worker内嵌空包的实际二进制，独立个人端部署包包含相同文件。GET下载和HEAD响应均提供实际SHA-256，代发独立包不暴露写作包下载入口。
2. 统一工作台、配置、模块和部署包元数据为1.4.3，写作内核保持4.3-quality。ZIP采用固定条目元数据；相同源码可生成逐字节相同的交付包。
3. 个人端与代发端共用的正式阅读流程补查冻结开关、清单数量、每章正文及记录的冻结版本。索引哈希重新生成也不能绕过冻结异常。未启用连载的旧作品仍保留只读兼容。
4. 维护恢复检查点与普通blocked分开显示。只有检查点与当前作品、state哈希和下一章匹配，才显示等待原任务核验；日更、补更指令补充operator_revocation分支，不把检查点当作章节完成，也不允许普通任务自行制作维护授权。
5. 新包中的操作文档去掉旧作品接入记录、真实旧书核验段落与界面截图；不包含管理清单、旧book_id、正文、旧运行锁或任务绑定。生成指令和启动说明明确：当前默认分支被作者清空后，不从历史恢复旧书。
6. 列表旧基线标注为“接入时”，避免把历史章数误显示为本次已读取的当前进度。
