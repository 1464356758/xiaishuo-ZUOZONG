# V4.3 复查与修复记录

日期：2026年10月25日。复查基线：`d01c1eaab2588c7f8011dec8d188390cfb9d31a0`。

本轮针对已上线母版重新检查资料组装、版本失效、冻结和恢复路径，并用新增回归用例复现边界问题。没有创建新小说或修改小说正文。

## 复查结论

发现并修复四类边界问题。修复保留V4.3现有报告格式、单GPT入口、三轮返修、采用即冻结和真实发布登记规则；不引入新评分体系。

### 1. 空读者回顾会漏掉旧章内容

原来较早章节只要存在`reader_updates`列表，就可以被当作回顾使用；列表为空时，资料包中只有空列表，却把该章标为回顾覆盖。这会让该章已发生的内容从前情资料中消失。

现在只有非空、带证据的回顾可以替代较早正文。回顾为空或缺失时自动读取该章实际正文，覆盖类型标为full_text。资料过长仍须分批，不静默省略。

回归用例专门让第一章有独特事件、回顾为空，再推进到第四章；确认下一章资料仍包含第一章原文。

### 2. 资料生成的来源检查存在时间空隙

原先writer／reader资料在加载state并校验文件之后才读取“开始时的状态哈希”。如果状态恰好在这之前发生变化，旧state与新哈希可能被配在一起，末尾检查无法发现。author资料原来只比revision，也会漏掉不增加revision的状态变化。

现在三个视角都将最终state与最初载入的完整state比较。reader同时重新核对候选文件内容，草稿在组装期间发生变化就停止，让执行者重新读取。

回归用例模拟文件校验时改变revision或标题，分别检查author、writer、reader；另模拟组装途中改变草稿。这是来源一致性检查，不宣称跨机器文件操作具备数据库事务能力。

### 3. 输出路径误填可能覆盖候选草稿

原先`context --profile reader --text 某草稿 --out 同一草稿`会把资料包覆盖到草稿文件，虽然后续哈希检查会失败，仍造成不必要的稿件损失风险。

现在输出路径解析后若与当前输入草稿相同，会明确拒绝，保持草稿原样。原有“输出不得进入book目录”的保护继续保留。

### 4. 无效检索词和范围统计不够严格

纯分隔符或标点此前能通过非空字符串检查，实际没有有效查询词。现在历史查询、任务书和发布前报告共用有效词判断，这类输入均被拒绝。

检索结果同时区分`indexed_records`与`scanned_records`：前者是全书索引条数，后者是本次参与查询的条数。使用`--before`过滤范围后，不把排除章节算作已查询。
